# 0.27.1

`VvLlmModelProvider.resolve()` now accepts a unique resolved endpoint model ID
when the requested name does not match a settings key. Provider wrappers can
delegate session model resolution even when a settings key differs from the
endpoint's model ID, while retaining their capability overrides.

Exact settings keys still take precedence. Model ID lookup stays within the
explicit or default backend; without either, it requires a unique match across
backends. Ambiguous IDs are rejected. This fixes issue #68.

This patch retains contract 29.1.0. There is no API, record, inbox, SQL, event or
App Server schema change.
