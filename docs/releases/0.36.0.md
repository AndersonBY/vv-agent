# 0.36.0

Status: **Unreleased**.

## What's included

P1 establishes `vv_agent.kernel` as the standard-library core boundary. Kernel
logic uses the standard library; the PostgreSQL driver is imported lazily only
by the store adapter. The kernel owns record, inbox, reducer, recovery, lease,
SQL, canonical JSON, and related decision logic. SDK adapters retain model,
network, file, archive, and other host-side effects. Import, public-API,
capability-matrix, and documentation reference checks enforce this split.

The seeded simulation drives the production kernel and SQL stores with
deterministic decision replay and mutation checks. The release workflow runs
the remaining suite with `TMPDIR=/tmp uv run pytest -k 'not simulation_smoke'`.
A separate smoke step uses `/dev/shm` and a 60-second timeout:

```bash
TMPDIR=/dev/shm timeout 60s uv run pytest tests/sim -k smoke -q -s
```

Contract 39 changes a failed closed session-schema check to report exactly
`invalid session schema`. Explicit semantic, parser, duplicate-member,
provider-result, and model-selection diagnostics retain their behavior.
Accepted and rejected values, validation order, canonical bytes, IDs, and
digests do not change. Consumers must not depend on complete
`jsonschema.ValidationError` text, paths, or schema dumps.

## Compatibility

Record schema 1, inbox schema 3, SQL layouts, RunEvent v6, App Server v5, frozen
definitions, and the public SDK entry-point inventory are unchanged. Existing
sessions need no migration, drain, decoder selection, or byte rewrite. The
existing `vv_agent.session` exports and facades remain available while concrete
stores live under `vv_agent.kernel`.

Backend integration needs no new DDL, `Principal`, or provider. Upgrade the
vv-agent dependency and handle the stable invalid-schema text without parsing
full validation exception details.

## Known limitations

- The canonical lock remains 38.0.0; contract 39 adoption is pending.
- `LocalWorker` is not implemented. Public entry-point convergence is P3 work.
- Local App Server, Interactive, and Runner entry points still treat yield
  declarations as undeclared waits, as documented in the
  [0.35 known limitations](0.35.0.md#known-limitations).
- L2-L5 remain unfixed. I9/W2c and I11/W4 are deferred with their later phases.
- Rust remains frozen at contract 23.0.0 and package series 0.21.x.

## Verification

Remote checks at Python commit `f5219a4` selected local canonical contract 39.0.0
at `ec154627`. The full correctness suite passed 7,915 tests on Python 3.12.12
and PostgreSQL 18.7 over TCP with password authentication. Only the six opt-in
live tests were skipped; the separate simulation smoke was deselected.

The 1,000-seed SQLite smoke covered all 21 scenarios in 20.76 seconds including
process startup and shutdown, using eight workers and `/dev/shm` with WAL/FULL.
The full correctness suite used ordinary temporary storage. These are separate
results; the smoke does not establish host-power-loss durability.

The million-seed SQLite campaign, PostgreSQL 10k campaign, nightly schedule and
central contract adoption remain pending. These results do not complete P1.

## Size review

files to 53,077 lines in 244 files: net +5,024 lines, with 20,586 insertions and

`session/kernel.py` fell from 2,401 to 314 lines.

The increase includes new request and host-adapter boundaries alongside moved
code; each phase keeps its own provider and memory lifecycle. Line
