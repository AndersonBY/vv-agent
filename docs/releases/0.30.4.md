# 0.30.4

Compaction checks for Kimi, Moonshot, Gemini, Claude, MiniMax, Stepfun and GLM
now count locally. Each uses vv-llm's no-endpoint fallback, so enabled
provider endpoints no longer receive the full conversation on every check.
The checks also avoid provider retry delays and constant failure counts.

The tiktoken fallbacks reuse the existing incremental path with the same
dependency version gates. MiniMax uses its whole-text character formula.
DeepSeek, other tiktoken models and Qwen keep their 0.30.3 behavior.
Hosts can see the local method and incremental eligibility through
`incremental_token_counting_status`.

These are context-size estimates. They can change when compaction happens
compared with provider counting. Review the host's threshold and context
headroom as described in [upgrading](../upgrading.md#0304) and
[token counting](../token-counting.md). No safety multiplier is added.
Direct vv-llm calls keep their previous behavior.

Contract 31.0.0 and all store formats stay unchanged. No migration is needed.
