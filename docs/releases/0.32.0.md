# 0.32.0

Adopts contract 32.1.1. Long tool results now keep their full text, and the
model can go back for it.

## What changed

**Every non-model tool result is projected the same way.** A result longer than
12,000 characters becomes a head-and-tail preview with a marker naming the
artifact path and both ways back. Shorter results pass through byte for byte.
Before this release, product tools and built-in tools each decided for
themselves what the model saw.

**The full text is archived, not truncated away.** The complete result is
written once to `.vv-agent/artifacts/<task>/<call>-<hash>.txt` through the
workspace backend's exclusive chunk writer, then verified. Writing streams in
chunks; nothing is held in memory as one string. A new write is confirmed from
the byte count the writer reports plus the backend's file size, so a 9 MB result
does not get read back to be trusted. Rebuilding a request for an existing
artifact re-verifies it with a full streaming digest.

**The receipt names its own provenance.** `metadata.vv_artifact` carries the
artifact reference, the operation and attempt that produced it, the tool call
ID, and the SHA-256 of the arguments. The reducer rejects a completion whose
`source` does not match the operation it belongs to, so a producer cannot forge
the namespace. `source_complete` says whether the archive holds the whole
result; when it does not, `capture_incomplete_reason` says why.

**`search_files` can search a retained artifact.** Give it one of these paths
and it streams that single file, matching line by line, and returns real
artifact line numbers that `read_file(start_line, end_line)` accepts directly.
Task scoping is enforced from the path's task segment. A line longer than the
match budget is reported as unmatched rather than silently skipped. The search
adds no archive and produces no new artifact reference.

A marker for a result the producer already shortened keeps its old 47-character
form and does not claim an artifact path, because there is nothing complete to
point at.

## Upgrading

Contract 32.1.1 is required; `contract.lock.json` pins revision `9a40c5b` and
the release artifact. Run `scripts/contract_snapshot.py check` after upgrading.

Record schema 1, inbox schema 3, SQLite user_version 3 and RunEvent v6 are
unchanged. This is not a store boundary and existing sessions load as they are.

Model-visible text changes for long results: a result that used to arrive whole
now arrives as a 12,000-character preview plus a pointer. Hosts that read
`metadata` should expect `vv_artifact` on exactly those results. Hosts that
capture tool output for their own display should keep reading the source they
already keep; the archive is the model's recovery route, not a replacement for
a product's own history.

The canonical rules for bounded prompts and tool results live in the contract
repository, `../vv-agent-contract/docs/prompt-bundles-and-tool-results.md`. The
vendored fixture snapshot under `tests/fixtures/parity/` carries the same wire
shapes; [parity-contract.md](../parity-contract.md) describes how it is synced.
