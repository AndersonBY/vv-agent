# 0.35.4

Runtimes now default to a 60-second execution lease. The
existing `Runtime.ttl_ms` setting remains the host control for the lease TTL;
the longer default covers sustained local concurrency while preserving lease
fencing.

`SQLiteStore` keeps the normal connection busy timeout at 5000 ms and opens
heartbeat connections with a separate 250 ms timeout by default. Set
`heartbeat_busy_timeout_ms` when constructing the store to tune the heartbeat
connection. The heartbeat retries SQLite lock contention for a bounded 5-second
window with 50 ms waits by default; hosts can configure that retry budget and
wait on `Runtime`.

The supervisor uses the runtime TTL when it defers a failed drive. A regression
scenario runs three concurrent parent tasks with two child sessions each while
a normal SQLite write transaction holds the database lock for 16 seconds. All
child leases renew after the lock clears and finish without duplicate execution
or `LeaseRetryExhausted`.

No SQL schema, record schema, inbox schema or contract version changes are
included.
