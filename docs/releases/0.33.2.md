# 0.33.2 — 2026-11-06

Requires contract 35.0.0. This patch fixes a model outcome classification defect.
The contract major records the observable behavior change, following the same
SDK patch/contract major distinction as 0.33.1.

An oversized input first follows the existing `prompt_too_long` compaction path,
including real HTTP 400 context errors and HTTP 413. Other HTTP 4xx responses except 408 are definitive failed attempts only when
every physical request in that logical invocation was observed and received
such a response. Vendor SDK retries are included; timeout→400 and 5xx→400 stay
Unknown. Unobservable host adapters require explicit ModelRequestRejected,
including for HTTP context errors that would otherwise enter compaction. Content rejection stops
immediately with `model_request_rejected`; it creates no Unknown receipt, unconfirmed operation
or duplicate-cost warning. Earlier genuinely unknown attempts still retain
their uncertainty and cost warning.

A 4xx is confirmed only after the complete raw response body reaches EOF and
decodes successfully. Unread/partially read bodies, early close and decoder
initialization/finalization failures stay Unknown, including for HTTP 413.
For every 4xx other than 408, the observer pre-reads and decodes within a total
wall-clock deadline of min(request read timeout, 10 seconds), using 10 seconds
when no read timeout is set, and a 1 MiB limit on raw and decoded bytes. Complete
bodies are cached for the vendor. Read/decode failures and either exceeded bound
stay Unknown. Failed reads are deferred until body consumption; on size/deadline
exhaustion, buffered raw bytes and the remaining original stream are replayed.
Pre-reading runs synchronously in the response hook and creates no threads.
Before the first raw read, the request's timeout extension is copied and its
read timeout shortened to the observation deadline. The loop checks total
elapsed time between chunks; the maximum extra network wait is the deadline
plus one recv timeout, at most 20 seconds. Remaining body reads keep that
shortened per-recv timeout, including after size/deadline exhaustion. A recv
timeout is saved and rethrown when the vendor consumes the body.
The observer never changes status, headers, Retry-After, x-should-retry, vendor
retry counts or backoff. Complete 409s, retry-enabled 400s and all-429 invocations
therefore reject definitively even when vendors discard intermediate bodies.

401/403/404 with multiple frozen endpoints try the next endpoint immediately;
with a single endpoint they stop after one call. 429 and adapter-confirmed
temporary rejections can retry within the existing `max(2, frozen endpoint count)`
limit; a single endpoint still gets one 429 retry. Each rejected attempt keeps
its receipt. The next attempt and its backoff are committed together; the delay
is zero for 401/403/404 and 2 seconds times the rejected attempt number for 429
and other explicitly retryable statuses. It survives worker restart. Exhaustion
is a definitive failure with the last safe rejection. 408, 5xx, timeout,
connection loss, cancellation and failure after stream output keep the existing
Unknown behavior.

Hosts get HTTP status, provider error code/type and a generic explanation of at most
500 characters in `op_completed.result.rejection` and failed-model event metadata.
The terminal result and failed-run event carry the safe status/message for users.
The adapter copies only status and safe code/type; arbitrary provider prose is
omitted to prevent bare-key, request-field and truncated-prefix leaks. Output
repair uses this same safe constructor and retains repair_provider_error and
output_validation_failed.

Custom clients can raise `vv_agent.llm.errors.ModelRequestRejected(400, message,
provider_code=..., provider_type=...)`. Explicit `retryable=True` or `False`
overrides the default endpoint policy, including the single-endpoint rule;
omitting it follows the defaults above. Automatic recognition accepts matching
real `httpx`/`httpx2` responses through explicit causes only with complete
SDK-owned HTTP-client observation. The complete exception graph is scanned for
uncertainty before accepting any rejection, including explicit assertions. A bare integer status,
unrelated exception context or unknown exception stays Unknown.

The veto includes installed OpenAI and Anthropic `APIConnectionError` types and
their `APITimeoutError` subclasses, even when the low-level HTTP cause is absent.
They are loaded when classification needs them; each vendor's ordinary import or
invalid-export failure is isolated, and only actual exception types are accepted.
Failed provider lookups are not cached; a recovered import restores network-error
vetoes on the next classification. Cancellation and process interrupts propagate.
Positive HTTP recognition still uses response and observation evidence, not
vendor exception classes or guessed class names. A context-length message wrapped
around a native network error stays Unknown and cannot be settled by compaction.

Prompt-too-long detection runs before rejection classification. It recognizes
existing text patterns and provider message/code/type fields such as
`context_length_exceeded`, even when the message says only that the input exceeds
a limit. HTTP 413 means the model input must shrink. `string_above_max_length`
qualifies for prompt/input/message content parameters; a tool-name length error
still fails as rejected. Timeout, transport/connection loss, 408/5xx, cancellation
and observed stream output take priority and remain Unknown. Compaction exhaustion
still ends with `CompactionExhaustedError`, never rejection.

Content rejection does not try the next endpoint. Endpoint-specific 401/403/404
and 429 advance through the frozen endpoint order within the existing limit.
Genuine Unknown failures keep their separate uncertain receipts and cost warnings.

A rejected ordinary compaction summary keeps the whole old context and continues
the primary call after any permitted retries. Error text is never a summary.
Output-repair callbacks keep their existing failure behavior.

There is no record, inbox, SQL, event, App Server or frozen-definition change.
Existing 0.33.1 turns can continue on the new runtime. handler_version stays
unchanged. **Globally stop all worker and API drivers, upgrade both machines,
then start them together. Any session driven by 0.33.2 MUST NOT return to 0.33.1;
rollback MUST isolate data by host-maintained version ownership.** Include
recovery scans, retries, waits, children and finished-history readers. Permanent
rejection before turn_ended can be misdriven by 0.33.1; its reducer rejects
rejection retry histories. A lease does not guard versions.

`scripts/check_model_rejection_rollback.py::check_store(store)` reads all history
without writes and flags rejection records, unfinished rejection turns and
rejection retry plans. Run it while drivers are stopped; errors block rollback.
A clean scan cannot replace the host's ownership exclusion. Usage and full stop/
rollback rules are in [upgrading](../upgrading.md#0332--2026-11-06).

A ledger attempt is one logical adapter invocation, not one physical HTTP send.
The SDK passes an observed httpx2 client to vv-llm and closes it after the logical
call. Current vendor defaults may send three HTTP requests within one attempt;
the kernel's two-attempt 429 limit can therefore send six requests. Safety does
not depend on disabling those retries. vv-llm is unchanged and unpublished.
The observed clients inherit the corresponding vendor's exported defaults:
connection limits and, for Anthropic, platform-specific TCP keepalive options.
Explicit endpoint proxies still take priority over environment proxies;
`trust_env=False` disables those environment routes, and per-request timeout
settings still override the client default. Failures are assigned to their own
send, including concurrent sends and redirect hops. A failure without an index
permanently vetoes rejection for that invocation. Closing a callback-aborted
stream explicitly closes its iterator and every retained HTTP response before
closing the client. `httpx2>=2.7,<3` is now a direct dependency, matching vv-llm.

Hosts must preserve the original exception graph and observation. In particular,
remove quota/context-length text wrappers that raise a new unrelated error.
Put friendly display text in the host's failure projection instead. Upgrading
the package alone does not verify that host adaptation.
Existing Unknown receipts are not rewritten or settled. Hosts map the new
terminal reason to FAILED and display the safe error.
