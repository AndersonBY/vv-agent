# 0.34.0

New sessions retain inputs until a primary model response has been committed to
the session history. A rejected request, endpoint retry, Unknown receipt or
successful summary cannot make those inputs eligible for compression.

Summary planning, acceptance, emergency compaction, microcompaction and replay
preserve the same protected suffix, including complete tool batches. Host hooks
that remove it raise `UnseenInputError` (`unseen_input_removed`) before a plan is
committed. Inputs that cannot fit without being shortened end the turn with
`unseen_input_capacity_exceeded`.

Creation freezes the choice in `attributes.seed.unseen_input_protection`.
Existing sessions without it keep their original replay and continuation rules.
Children and App Server forks inherit the parent's choice. Python 0.33.3 rejects
the new seed declaration when decoding creation, reading from the beginning or
restoring a session. Hosts must check versions themselves for paged, inbox and
raw JSON reads. Do not send declared sessions to an older runtime. Once an old
parent creates a child in the new format (including explicit false), keep both
parent and child execution, cancellation and result delivery on the new runtime.
The parent creation record alone cannot establish rollback safety.

This implements contract 37.0.0. Contract publication, lock/snapshot selection and
central adoption remain release gates. Rust stays frozen at contract 23.0.0 and
does not support this feature.


Model completion now uses vv-llm >=0.10.1. New sessions declare
`attributes.seed.response_rejection=true`. A content-filter result, or refusal
finish reason without answer text, now ends as `model_request_rejected` with
HTTP 200, safe provider code/type and `retryable=false`. A streamed answer may
already be visible: finish or replace that temporary text when ModelCallFailed
or RunFailed arrives. Rejected partial text is not retained in model history.

OpenAI refusal text is an ordinary answer when the reason is not content_filter.
If content is empty, that text becomes the assistant body, so hosts should render
it as they render any assistant answer. Final evidence is available in ordinary
model receipts at `raw.completion_metadata`. Missing-termination EOF follows
existing Unknown/retry behavior; degraded observation is recorded as unknown
termination and keeps existing completion behavior.

No record, inbox or SQL schema changes. Existing sessions without the response
policy retain 0.33.3 filtering behavior; EOF and refusal-text improvements use
representations 0.33.3 can read and continue. Both seed policies independently
default on only at first creation, inherit on child/fork (absence becomes false),
and preserve creation bytes on transaction replay. 0.33.3 rejects either declared
field, including false. Keep declared sessions and dependent parent/child work on
the new runtime when rolling back; do not strip creation fields to bypass this gate.

Normal tool callbacks arriving after a before-memory snapshot update the same
committed message projection used by requests, protection checks and replay.
Replacements retain the positions of every original tool group kept verbatim,
including groups whose earlier input is already covered. App Server creation
retries reuse the winning node's baseline and delegate replay to the transaction.
