# 0.31.2

Fixes streamed tool calls getting mixed up when a model opens two or more
calls at once ([#67](https://github.com/AndersonBY/vv-agent/issues/67)).

Before this release, a streamed piece of tool-call arguments that came without
a tool name always went to the call opened last. If a model opened calls A and
B and then sent more arguments for both, A's arguments were appended to B and
both calls ended up with broken arguments.

Now a piece goes to the call with the same call ID. Without an ID, it goes to
the call that most recently opened at the same `index`. This keeps the common
shape working where vv-llm reports every call at index 0 one after another.
A piece with a tool name but no ID always starts a new call, so two calls to
the same tool stay separate. If several calls are open and a piece carries
neither ID nor index, vv-agent no longer guesses: it drops that piece instead
of writing it into the wrong call. Progress events follow the same call as the
arguments.

Known limit: vv-llm 0.8.4 replaces each tool call's `index` with its position
inside the current chunk. When a provider interleaves several calls one piece
per chunk without IDs, the original identity is already gone before vv-agent
sees it, and those streams can still be assembled wrongly. vv-llm 0.8.5
resolves this limit by preserving the provider's index. Use
[vv-agent 0.31.3](0.31.3.md) to also keep incremental token counting enabled
with that dependency.

No contract, wire, store or dependency change. Contract 32.0.0 is unchanged.
