# 0.22.0

Python 0.22.0 adopts contract **24.0.1**, public API **v8** and App Server
protocol **v2**. Runner, RunHandle, interactive sessions, CLI, App Server and
children execute through one session kernel with SQLite or PostgreSQL stores.

## Breaking changes

- Retained session/turn identities replace checkpoint snapshots and old resume
  APIs. Execution backends, distributed entrypoints, Redis stores and historical
  wire readers are removed. Follow the [v8 migration guide](../migration-v8.md)
  for replacements, creation-time seeds and handling old running executions.
- The supported extras are `postgres`, `s3` and their combination. The removed
  `redis` and `celery` extras add no dependencies; installing them does not
  restore retired features.
- Celery and Redis belong to the host. Hosts assemble runtime bindings, commit
  inbox inputs and projections with their PostgreSQL transactions, dispatch
  `drive`, and schedule `tick`. See [host integration](../host-integration.md).
- Current codecs reject missing, stale, malformed and unknown versions/fields.
  Older runtimes remain available through their pinned Git tags.

## Scheduling

Accepted provider jobs are queried on the session's schedule: first at
`poll_at_ms`, then at most once per poll interval. Duplicate or reordered wakes
and unrelated inputs do not trigger an early query. Authenticated provider
results, controls and replies are applied immediately, and deadlines keep their
due time. An in-process run returns as soon as its turn parks on a provider
wait; a host `tick`, a wake or `Runner.resume` at the due time continues it.

## Compatibility

Contract 24.0.1 is centrally verified for Python. The Rust implementation stays
frozen at contract 23.0.0 (package series 0.21.x).
