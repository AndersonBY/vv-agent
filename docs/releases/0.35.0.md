# 0.35.0 SQL core preparation

This change adds opt-in observation interruption to the SQL kernel and corrects
heartbeat latch ordering. It does not establish release acceptance; local yield
scheduling and canonical contract/producer adoption are pending.

Foreground children can declare `ChildSession(yield_on_steer=True)`. Providers
can return `Accepted(handle, yield_on_steer=True)`. If every unfinished member
can yield, one append completes the observations, applies steering and consumes
the input. Verified child terminals at the same watermark take priority.

Optional read-only renderers on ChildTool, SummaryChildTool and provider bindings
supply the model-visible result. Replay keeps that committed result. Yielding
leaves children running and stops querying or cancelling the provider handle.
Later authenticated evidence follows the background or audit rules.

Polls serialize snapshot, renewal and publication without holding the commit or
state latch across store calls. Per-object thread-local entry guards reject
synchronous poll reentry before latch acquisition and through release. TTLs,
heartbeat intervals, timeout limits, retry classes and lease fences are unchanged.

Public drive and dispatch-only tick use the supplied store instance. Admission
and Runtime.hook signatures are unchanged. No SQL DDL or record/inbox version
changes are included. Older readers reject sessions containing the new closed
fields. Undeclared waits retain their behavior, and stored 0.34.1 long receipts
keep their selected archive references. New long candidates bind archive identity
to content so a discarded render cannot overwrite a committed observation.

See [session kernel](../session-kernel.md#yielding-an-observation-to-steering)
and [upgrading](../upgrading.md#0350-sql-core-preparation).
