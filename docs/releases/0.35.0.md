# 0.35.0

## What's included

The SQL core supports opt-in observation interruption. Foreground children can
use `ChildSession(yield_on_steer=True)`. Providers can return
`Accepted(handle, yield_on_steer=True)`. When every unfinished observation can
yield, one commit completes those observations, applies steering and consumes
the input. Verified child terminals at the same watermark take priority.

Read-only renderers on ChildTool, SummaryChildTool and provider bindings can
supply the model-visible result. Replay uses the committed result. Yielding
leaves children running and stops querying or cancelling the provider handle.
Later authenticated evidence follows the background or audit rules.

L1 corrects heartbeat lock ordering. Polls serialize snapshot, renewal and
publication. Renewal holds neither the commit latch nor the state latch across
store calls. Synchronous poll reentry on the same heartbeat raises RuntimeError
before taking a latch. TTLs, heartbeat intervals, timeouts, retry classes and
lease fences stay the same.

Public `drive` and dispatch-only `tick` use the supplied store instance.
Admission and Runtime.hook signatures stay the same. No SQL DDL or record/inbox
version changes are included. Existing 0.34.1 sessions remain readable. Older
readers reject sessions containing the new closed fields. New long result
candidates bind archive identity to content; committed 0.34.1 receipts keep
their selected archive references.

## Known limitations

- App Server, Interactive and local Runner/RunHandle entry points accept wait
  declarations but treat them as undeclared waits. Steering stays pending until
  the normal result arrives. These entry points do not provide yieldable waits
  in 0.35.0. See `tests/session/test_local_wait_declarations.py`.
- Do not run a whole `drive` or `poll` while holding an outer host write
  transaction. Leaving a savepoint does not release that transaction's locks.
- Concurrent native transactions that share one raw connection between the
  runtime and host are unsupported. The SDK does not promise to detect them.
- L2–L5 are recorded and remain unfixed: cleanup evidence and full handoff
  after stop (L2), control-token lifetime (L3), opaque deadline start (L4), and
  SQLite busy classification (L5).

See [session kernel](../session-kernel.md#yielding-an-observation-to-steering),
[host integration](../host-integration.md) and [upgrading](../upgrading.md#0350--2026-11-12).
Canonical contract adoption and release validation are separate release gates.
