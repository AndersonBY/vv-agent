# 0.31.3

Requires vv-llm 0.8.5 to finish the streamed tool-call fix from
[0.31.2](0.31.2.md). vv-llm now keeps the provider's tool-call index instead
of replacing it with the piece's position in the current chunk.

When a provider sends A's first piece, B's first piece, then more arguments
for A and B in separate chunks, each continuation now reaches the right call.
Progress events follow the same call as the arguments. Sequential calls that
all use index 0 still work. Providers must supply a stable index or call ID
for interleaved calls.

Local incremental token counting now accepts vv-llm 0.8.5 paired with
deepseek-tokenizer 0.3.0 or tiktoken 0.14.0. Upgrading vv-llm therefore keeps
the cached counts for unchanged text. Unverified versions and unsafe text
boundaries still use whole-conversation counting.

Contract 32.0.0, App Server v5, record schema 1, inbox schema 3 and SQL layouts
are unchanged. This release has no store boundary or migration.
