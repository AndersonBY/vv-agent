# 0.33.1 — 2026-11-05

Requires contract 34.0.0. The contract's major version follows its observable
behavior policy; the SDK patch fixes the search regression introduced by 0.33.0.

0.33.0 incorrectly limited the whole search to 250 ms of cumulative thread CPU,
including enumeration and per-line Python work. On vectorvein.ai, regex and
literal scans of a 1.92 MB, 40,000-line artifact stopped around lines 24,009 and
25,809 before the target on line 33,333. The request limit is now 10 s of thread
CPU. Each individual regex engine invocation (one line, window or whole text)
gets a separate interruptible 250 ms timeout, capped by the remaining total.
finditer shares that timeout across its iteration, without resetting per match.

Both limits preserve earlier content hits and interruption coordinates. Single
engine timeouts say "Regular expression too slow; aborted"; total exhaustion says
"Search total CPU limit exceeded (10 s); aborted". Discovery failures remain
explicit errors. Local, Memory, S3, artifact search, find_files/globs and child
exclusion filters share these rules and retain enumeration-loop checks.
Window, overlap, output page, head_limit and file size limits are unchanged.

This changes handler behavior only. Tool schemas, frozen turn definitions,
record schema 1, inbox schema 3, SQL schema 3, RunEvent v6 and App Server v5
are unchanged. Upgrading from 0.33.0 needs no frozen-turn transition or old
decoder branch. Upgrades from earlier versions must still follow the
[0.33.0 transition](../upgrading.md#0330--2026-11-04).

Frozen Rust remains at contract 23.0.0 / package series 0.21.x.
