# 0.27.0

Hosts can expose a tool that requests context compaction. The handler returns
intent; the kernel logs a separate summary model operation after the batch,
accepts the context replacement, and commits memory telemetry before the next
primary cycle. Repeated requests in a batch share that operation. Finish and
wait-user take precedence. No eligible history or a failed summary keeps the
original context.

`SummaryChildTool` prepares a fresh full-history summary before custom child
admission. It passes accepted text to the host callback, which writes child
input on the admission transaction. The parent's context stays intact. A saved
summary receipt survives a restart and does not make another paid request.
Missing receipts use the existing Unknown retry and duplicate-cost rules.

SQLite shutdown now waits for an in-flight store read before closing its
connection. This prevents a native crash when an App Server reader overlaps
shutdown.

This minor package release adopts contract 29.1.0 and public API inventory v13.
There is no record, inbox, SQL, event or App Server boundary. Existing 0.26
records remain readable. See [upgrading](../upgrading.md#0270) and the
[host examples](../host-integration.md#a-compact-tool-and-fresh-child-summaries).
