# 0.30.0

Runtime factories keep their lease alive throughout preparation, including builds
longer than the starting 15-second TTL. The kernel renews before the factory,
uses the latest lease for success, readiness deferral and exception cleanup,
applies the returned runtime's TTL, and joins the preparation heartbeat on every
exit. A renewal failure or fenced epoch prevents driver execution.

State reads capture one committed head, inbox watermark and epoch. Record reads,
consumed-input validation, folding and snapshot copying stay within that prefix
and run without a session row lock. Schedule preparation and App Server input
and compaction admission move history reads ahead of their write locks and
recheck the head before mutation. PostgreSQL append history preparation also
precedes its session row lock. New-record validation and transactional host
writes retain their existing atomicity and fencing.

Hosts can drop `RuntimeFactoryStore`. Custom stores provide `heartbeat_store()`;
host-managed PostgreSQL adapters should return their independent connection
factory. Existing `read_state` call signatures and result shapes are unchanged.
Hosts must keep long reads outside outer write locks/SQLite write transactions,
and bound SQL and callback I/O so heartbeat shutdown can finish.

Adopts contract 31.0.0. Record schema 1, inbox schema 3, SQL layouts, SQLite
user_version 3, public API inventory v14, RunEvent v6 and App Server v4 are
unchanged. No store boundary. See [upgrading](../upgrading.md) when moving from
0.27.x, especially for App Server client regeneration.
