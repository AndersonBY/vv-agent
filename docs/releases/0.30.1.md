# 0.30.1

Cold session loads stop decoding message snapshots that a later full snapshot
replaces. Each boundary still checks its source digest against the state at that
point. Folding no longer copies the entire history list for each boundary.
Result projection groups tools by their model operation once, and event
projection copies returned events instead of retaining detached model requests.

PostgreSQL reads use binary results for record bodies. Parsed canonical records
share their original byte buffer with the validated prefix. Cold loads fetch
records in pages and share equal private message values across snapshots.
The fold validates each retained message value once and reuses its canonical
fragments when checking requests and boundary sources. It still hashes the full
canonical content for every digest check. Public payloads,
messages, events and state snapshots remain detached from the retained data.

The version stays on contract 31.0.0. Record schema 1, inbox schema 3, SQL
layouts and all public shapes are unchanged. No store boundary or migration.
Existing sessions keep their stored bytes. Full request and boundary message
snapshots remain in the log; this release does not change their storage format.

Record JSON parsing uses jiter with duplicate-key rejection. The standard JSON
reader preserves existing inputs and error handling when the fast reader rejects
an input. orjson builds private equality keys only; persisted bytes and protocol
digests still use the RFC 8785 encoder. jiter and orjson are explicit runtime
dependencies.
