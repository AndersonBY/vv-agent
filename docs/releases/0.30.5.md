# 0.30.5

PostgreSQL heartbeats keep renewing during child admission and `before_commit`.
Those callbacks no longer hold the Python state lock needed by renewal.
Append finishes encoding and history preparation, then takes the current Lease
under a latch shared with renewal. The latch remains held through commit.
PostgreSQL row locking also allows child foreign-key checks to coexist with
renewal.

Fencing stays strict: renewal cannot revive an expired lease or change its
owner or epoch. Append still checks owner, epoch, database expiry, Lease expiry,
head and inbox watermark. A genuinely fenced admission rolls back as a batch.

The built-in PostgreSQL heartbeat connection bounds connection establishment,
lock waits and statements. Heartbeat renewal retries timeouts and operational
errors while the last published Lease has a safety margin. Factory setup uses
the same retry rule. Host-provided PostgreSQL heartbeat connections receive the
same lock and statement limits. The final append allows SQL to use the remaining
Lease time, then restores the host's timeout settings, including inside an outer
transaction.

Each `close()` waits at most 6 seconds and reports
`LeaseLost` if the heartbeat thread has not exited. It cannot release the lease
or hand off to a runtime while that thread is still running.

The module logger reports transaction phase durations after leaving the kernel
transaction. A phase taking at least half the lease TTL produces a WARNING,
without logging arguments, contents or exception messages. Hosts must still
keep transaction callbacks short and bound their I/O. See
[callback requirements](../host-integration.md#transaction-callbacks).

Known limitation: admission recovery still rolls back and permits a redo.
The durable admission stop rule is deferred. With the heartbeat fixed, a long
callback alone does not force a redo; a real worker crash or database lease loss
can still do so. External effects need host-owned deduplication and recovery.

Contract 31.0.0 and all store formats stay unchanged. No store boundary or
migration is needed.
