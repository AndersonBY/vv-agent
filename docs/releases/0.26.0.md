# 0.26.0

Endpoint edits no longer stop live sessions with definition drift. Model
identity includes backend, model ID and both model limits. Routing is resolved
for each new operation and its endpoint order stays fixed through attempts.

Hosts get their `VvLlmClient.ordered_targets` policy after model selection as
well as for default plans. A preferred endpoint is a hint to that policy.
Resolvers must handle default requests as well as selected ones.

An endpoint removed before dispatch produces `endpoint_unavailable` with no
provider call, empty usage and `execution_started=false`. The next primary
cycle uses current routing. Started attempts keep their original evidence.
The Unknown retry limit and one endpoint per attempt rule are unchanged.

This release adopts contract 29.0.0. It is a minor package release because
hosts must update endpoint identity checks and default resolver handling.
There is no store boundary: 0.24 and 0.25 records remain readable, with no
record, inbox or SQL schema version changes. See [upgrading](../upgrading.md#0260).
