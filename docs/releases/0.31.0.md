# 0.31.0

This release adopts the published contract 32.0.0, App Server v5 and public API
inventory v15. App Server clients must upgrade their bindings before connecting.

## What changes for hosts

Hosts can register named job providers through `RunConfig.tool_providers`.
The kernel checks final results against the original tool call, attempt and
acceptance evidence. Invalid results report `provider_result_invalid` and leave
the job unresolved. Hosts must restore named bindings after restart; a missing
binding reports `missing_host_binding`. Only an explicit `function` binding
selects the synchronous handler. A cancellation receipt acknowledges the request;
external work can remain unconfirmed after the turn ends.

Completed tool items now contain a size-limited result descriptor. The raw body
and arbitrary metadata have been removed from the `tool_result` diagnostic.
Use `thread/toolResult/read` to read pages of the retained body or a file or
image resource. Hosts must implement `AppServerHost.authorize_tool_result_resource`
to authorize each resource page.

Workspaces can opt in to `OutputRetentionBackend`. Backends that already keep
immutable versions can retain them without making another copy. Other backends
keep private snapshots. Without retention support, file and image resources are
`not_retained`. Backends must support offset and length reads and check the
immutable version on every page without hashing the whole resource each time.

User questions now expose a retained form in status, snapshot `state` and event
replay. The old `respond.message` field has been removed. Send `respond.target`
to identify the exact question and `respond.answer` for the typed answer.
Free text remains legal for every form, including choices that forbid custom
selections. The model-visible `ask_user` result now labels the reply as
`free_text` or `selection`. Choice answers must match the retained form.
See [user interactions](../app-server-interactions.md) for wire examples.

Direct host text replies through the inbox still work when they identify the
interaction, turn and generation. Answers to child sessions follow the recorded
parent-child relationships. Ordinary child messages queue steering instead of
guessing which question to answer. Parent cancellation also processes queued
cancellation controls for descendants.

## Store and projection changes

There is no session store boundary. Record schema 1, inbox schema 3, SQLite
`user_version` 3 and RunEvent v6 stay unchanged. Existing stored records and
older applied text replies still load.

Reprojected events can have different bytes under the same stable event IDs.
Hosts that keep immutable product projections must version or rebuild them
before using the new result and interaction shapes.

## Upgrade steps

1. Upgrade the package to `vv-agent==0.31.0` and regenerate App Server v5 bindings.
2. Restore all named providers on restart and update their result and
   cancellation handling.
3. Replace `respond.message`, update `ask_user` answer parsers, and read full
   tool output through `thread/toolResult/read`. Add resource authorization and
   update any output-retention backend.
4. Update product projections for the new descriptors, interaction metadata and
   snapshot `state` before moving active sessions to the new runtime.
5. Replace private `vv_agent.session.kernel._HeartbeatStopped` imports with
   `vv_agent.HeartbeatStopped` to distinguish intentional heartbeat shutdown from
   lease loss.

See [upgrading](../upgrading.md#version-notes) for host integration details.
