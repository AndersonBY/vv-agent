# 0.31.0 (unreleased)

This release adopts contract 32.0.0, App Server v5 and public API inventory v15.
Record schema 1, inbox schema 3, SQLite user_version 3 and RunEvent v6 stay the
same. There is no session store boundary. Hosts still need updated runtime
bindings and product projections before moving active sessions to this version.

Hosts can register named job providers through RunConfig.tool_providers. The
kernel validates definitive results against the original call, attempt and
acceptance evidence. Invalid results and missing bindings retain unresolved
work. A cancellation request can remain unconfirmed after its turn ends.

Tool items carry bounded result descriptors. thread/toolResult/read pages the
exact retained body or an authorized immutable resource. Workspace retention is
optional; existing immutable versions can be retained without a second copy.
Range readers check size and version on every page and avoid hashing the whole
resource for each page.

User questions expose one retained typed form in status, snapshot state and
replay. respond takes target and answer. Free text remains legal for every form
and is explicitly labeled free_text in the model-visible ask_user result.
Selections must match the form. Direct inbox application checks the same rules.
Child targeting follows the admitted graph, ordinary child messages queue
steering, and parent cancellation also drives queued descendant cancellation.

Use the public HeartbeatStopped signal when distinguishing intentional heartbeat
shutdown from lease loss. See [upgrading](../upgrading.md#version-notes) for the
host changes and [user interactions](../app-server-interactions.md) for wire examples.
