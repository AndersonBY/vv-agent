# 0.23.0

Atomic custom-child batches and isolated dispatch supervision close the host
integration gaps. This minor package bump is required by the new store methods
and SQL schema; 0.22.1 would incorrectly describe a behavior/API change as a patch.
Python 0.23.0 adopts contract **26.0.0** (local candidate) and public API **v10**.
0.23.0 is unpublished and untagged, so this change folds into that candidate.

- Runtime.children accepts one child or a nonempty uniform-background sequence.
  Host rows, all children/inputs, parent park and background receipt commit
  together. Invalid batches reject with InvalidChildBatch and roll back.
- Tick dispatch mode hands identities to host transport, isolates each item and
  raises failures together after the scan. Default inline mode remains available.
- Scheduled drive accepts a runtime factory under its lease. RuntimeNotReady
  defers input preparation without a failed terminal. Factory/driver errors use
  bounded SQL retry and remain visible. Projection failures back off separately.
- Required Store methods: defer_drive and defer_projection. Two nonnegative
  default-zero SQL retry columns; SQLite database user_version 2 rejects v1 files.
  Record schema 1, event and App Server wire shapes are unchanged.
- Inbox schema 2 requires provider_result.usage as a JSON object (`{}` means no
  observed usage). Schema 1 rejects. Authenticated late results retain usage in
  canonical completions and typed billing projections, including audit attempts.
  Replays compare result and usage canonical bytes and never bill twice.
  RunEvent v6, model-call v2, task-token-usage v3 and TokenUsage v1 stay current.

Follow [host integration](../host-integration.md) and the
[migration update](../migration-v8.md#python-0230--public-api-v10-host-update).
Hosts own finite callback/SQL timeouts and expired/coalesced queue deliveries;
inline tick cannot bound scan time independently of drive duration.
Rust remains frozen at contract 23.0.0 / package series 0.21.x.
