# 0.23.0

Contract **26.0.0**, public API **v10**, inbox schema **2**.

This release closes the gaps a distributed host hit when it ran vv-agent under
its own queue. It is a minor bump because custom stores need new methods and
the SQL schema changes.

- `Runtime.children` can return one child or a nonempty sequence of children
  that are all background or all blocking. Host rows, every child and its first
  input, the parent's park record and the background receipt commit together.
  An invalid batch raises `InvalidChildBatch` and rolls back.
- `tick` has a dispatch mode: it hands session identities to the host's queue,
  isolates each item, and raises all failures together after the scan. Inline
  mode is still available.
- A scheduled `drive` accepts a runtime factory and calls it under the lease.
  `RuntimeNotReady` defers input preparation without failing the turn. Factory
  and driver errors back off in SQL and are re-raised. Projection failures back
  off separately.
- Stores must implement `defer_drive` and `defer_projection`.
- `provider_result` must carry `usage` as a JSON object (`{}` when nothing was
  observed). Late and audit results keep their usage in canonical completions
  and typed billing projections. Replaying the same result and usage never
  bills twice.

## Store boundary

Inbox schema 2 rejects sessions written by 0.22.x. PostgreSQL gains two
nonnegative, default-zero columns: `sk_session.drive_retry_at_ms` and
`sk_consumer.project_retry_at_ms`. SQLite files use `user_version` 2 and reject
version 1. See [upgrading](../upgrading.md#0230).

RunEvent v6, model-call v2, task-token-usage v3 and TokenUsage v1 are
unchanged. Hosts own finite callback and SQL timeouts and must expire or
coalesce queued deliveries; inline `tick` cannot bound scan time separately
from drive time. Rust stays frozen at contract 23.0.0 / package 0.21.x.
