# 0.33.3 — 2026-11-06

Quota and time-window failures now reject instead of triggering compaction.
The generic `too many tokens` and `request too large` matches are ignored when
the same text contains a bounded time-window/quota signal. `too many tokens
per request` on 400 still compacts. Explicit context markers on non-429 4xx
retain priority even when quota is mentioned. `context window exceeded` and
`model context window is ...` now recover; the numeric maximum-model-context
wording is covered by the existing `maximum context length` marker.

On 429, only `context_length_exceeded`, `prompt is too long`, `prompt_too_long`,
`maximum context length`, or `string_above_max_length` with its existing content
param restriction qualifies. Other 429s retain rejection/backoff. Adapter
ModelRequestRejected flags use the same rule before safe diagnostic replacement.
HTTP 413, graph traversal, observation requirements and uncertainty vetoes stay
unchanged. Primary and summary callers share the kernel classifier.

Real local HTTP kernel tests cover both OpenAI and Anthropic: 429 per-day quota
produces two logical attempts and six physical requests; 400 per-minute quota
produces one request. Both end as model_request_rejected without compaction.

No dependencies or persistence/protocol versions change. Contract 36.0.0 is
required for the canonical behavior under its major-change policy. Local gates
use VV_AGENT_CONTRACT_SOURCE; immutable lock/snapshot synchronization and central
adoption are still release steps. The checked-in lock remains 35.0.0 until then.
See [upgrading](../upgrading.md#0333--2026-11-06) for the host transition.
