# Answer a user interaction

Read `pendingInteraction` from `thread/status`, a `thread/status/changed`
notification, or `state` in a `thread/read` or `thread/resume` snapshot. The
server shows one question at a time. Approvals have `kind="approval"` and keep
using `approval/resolve`. User questions have `kind="user"` and include:

- sessionId, turnId and generation identify the session that owns the question;
- interactionId, operationId and attempt identify the retained wait;
- requestDigest covers the normalized public form and its identity using
  SHA-256 of RFC 8785 canonical JSON, excluding kind and requestDigest;
- prompt and answerSpec describe the question and legal selections.

For a no-tool wait, operationId and attempt are both null. answerSpec contains
kind (`text`, `single` or `multi`), options, and allowCustomOptions. A text form
has no options and has allowCustomOptions=false. The server reads this form from
the log, so restarting with different host configuration does not rewrite it.
Event replay carries the same form in metadata.interaction on
HostInteractionRequestedEvent, or RunStateChangedEvent for a no-tool wait.

Copy the seven identity fields into target and send a typed answer:

```json
{"threadId":"parent","turnId":"parent/turn/run","actionId":"reply-1",
 "action":{"kind":"respond",
 "target":{"sessionId":"child","turnId":"child/turn/start","generation":0,
 "interactionId":"interaction/operation","operationId":"operation","attempt":1,
 "requestDigest":"cccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccc"},
 "answer":{"kind":"single","selected":["PDF"],"custom":[]}}}
```

Use `{kind:"text",text:"..."}` for any free-text reply. This is legal even when
the form offers options and disallows custom selections. The model receives
`{reply_mode:"free_text",text:"..."}` as the ask_user result. A selection instead
produces `{reply_mode:"selection",selection_type:"single"|"multi",selected:[],custom:[]}`.
The distinction lets a person explain an answer without pretending to select an option.

Single answers contain exactly one entry across selected and custom. Multi
answers contain 1..64. Selected strings must match an option exactly, with no
duplicates. Custom entries require allowCustomOptions=true. They are trimmed
using portable whitespace, must be nonblank, distinct, absent from existing
options, and at most 1 KiB UTF-8 each. Text is nonblank and at most 64 KiB UTF-8;
the whole canonical answer is also at most 64 KiB. Raw custom bytes remain in
the input receipt; only the model-facing value is normalized.

A prompt is at most 16 KiB UTF-8, with at most 64 options of 1 KiB each and a
64 KiB public form. ask_user reports interaction_form_too_large before opening
an oversized new wait. An oversized historical form reports that error and
keeps its wait. Options are never truncated during projection.

The server checks root and child authorization, follows real child admissions,
and writes the answer to the owning child's original inbox. Wrong turn returns
-32025, denial -32027, stale identity -32602 with reason=stale_interaction, and
invalid answer -32602 with reason=invalid_interaction_answer. Failure leaves
the wait intact. Two child questions can be answered in stable order. A waiting
child is never a final result for its parent. Parent cancellation also drives
the admitted descendants' queued cancellation controls.

The same actionId with the same target and answer replays the retained receipt,
even after completion or a server restart. Changed bytes return -32024
submission_conflict. A reply to an older question cannot answer the next one.

Direct kernel hosts can use `SessionDriver.answer` with InteractionReplyTarget
and InteractionAnswer. Typed InboxItem content uses the closed
metadata.interaction_response extension `{target,answer}`; text is generated by
the server and checked by the kernel. Existing host content `{text,interaction_id}`
also works when the envelope supplies the exact target turn and generation.
operation_id is optional on this text path, but must match when supplied. The
interaction id identifies the retained wait; no unique-wait inference occurs.
Child-task message APIs queue steering and cannot consume a human question.
The interactive client's prompt/continue_run convenience replies use the form
in its last displayed result. A stale client cannot answer a newer question;
reopening the session exposes the currently retained form.
